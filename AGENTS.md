# AGENTS.md

## What this is

Docker image that keeps IONOS/1&1 dynamic DNS subdomains updated by running the upstream
`domain-connect-dyndns` Python CLI on a schedule, plus an optional Next.js web UI to manage
subdomains. No tests, no Python deps file, no typecheck script — verification is
`docker build` at the root and `npm run lint` in `webui/`.

## Two runtime modes (`docker-entrypoint.sh`)

- `ENABLE_WEBUI=true` → `node server.js` (standalone Next.js build from `webui/`). The update
  scheduler starts in-process via `webui/src/instrumentation.ts` (Node runtime only), every
  `INTERVAL_UPDATE` seconds (default 60).
- otherwise → `python3 /src/updater.py`, a standalone APScheduler loop.

Both modes just shell out to `domain-connect-dyndns --config $CONFIG_PATH update --all`.
`CONFIG_PATH` defaults to `/config.json` (holds IONOS credentials after setup, gitignored —
never commit). The web UI binary is overridable via `DYNDNS_CLI`. Non-interactive CLI runs are
killed after `CLI_TIMEOUT` seconds (default 120) in both modes.

`/config.json` is normally a single-file bind mount: never `rename()` over it (EBUSY) —
`config-store.ts` falls back to an in-place write. The entrypoint exits if it is a directory.

## Web UI (`webui/`)

- Next.js 16 App Router + shadcn/ui + Tailwind v4. `webui/AGENTS.md` is auto-generated by
  `next dev` and warns that this Next version has breaking changes vs. training data — read
  `node_modules/next/dist/docs/` before writing code; don't fight the block.
- API routes: `api/domains` (GET list / POST add), `api/domains/[domain]` (DELETE remove),
  `api/domains/[domain]/setup` (GET session), `api/config` (GET file state / PUT validated
  save with backup + conflict detection), `api/update` (POST manual trigger). All handlers
  return errors through `src/lib/errors.ts` (`AppError` → code/HTTP mapping).
- Update outcomes are parsed from CLI stdout text in `src/lib/dyndns.ts`
  ("DNS records successfully updated.", "All records up to date", ...) — brittle coupling to
  the CLI's output; bumping the pip package may silently break it.
- Every config.json writer goes through one lock (`src/lib/config-lock.ts`, state on
  `globalThis`): the CLI reads the whole file, does network calls, then rewrites it, so any
  concurrent write is lost. Updates (`scheduler.ts`) fail fast with `CONFLICT`; editor save
  (`PUT /api/config`), remove and setup completion (`submitAccessCode`, held until the setup
  CLI exits) wait up to `CONFIG_LOCK_WAIT_MS`. New code that writes the config — directly or
  via the CLI — must take this lock.
- Setup sessions (`src/lib/setup-session.ts`) are in-memory only (module-level Map, 15 min
  timeout, URL scraped from CLI stdout) — lost on process restart.
- No authentication — README says only expose on a trusted network. `src/proxy.ts` (Next 16's
  renamed middleware) rejects cross-site non-GET `/api/*` requests (`Sec-Fetch-Site`, else
  `Origin` vs `Host`/`X-Forwarded-Host`); requests without those headers (curl) pass.
- Tokens never leave the server: `GET /api/config` masks `access_token`/`refresh_token` as
  `__SECRET_<sha256 prefix>__` (`config-store.ts` `maskSecrets`, regex on raw text so corrupt files
  are masked too); `PUT` restores them from the tokens on disk and compares `baseRaw` against the
  masked disk text. Never return raw config contents from a new endpoint.

## Development

- `webui/`: `npm run dev` (note: `instrumentation.ts` starts the real scheduler in dev too,
  and the CLI must be on PATH with a valid config), `npm run lint` (ESLint only), `npm run build`.
- Docker: `docker build -t ionos-domain-connect .` — context is repo root; `.dockerignore`
  excludes `webui/node_modules` and `webui/.next`. Python deps are pinned in
  `requirements.txt` (`domain-connect-dyndns==0.0.9` because of the stdout parsing,
  `apscheduler<4` because 4.x drops `BlockingScheduler`).
- CI (`.github/workflows/docker-image.yml`) runs **only on GitHub release published**:
  multi-arch buildx push to Docker Hub `b3ni/ionos-domain-connect`, needs
  `DOCKERHUB_USERNAME`/`DOCKERHUB_PASSWORD` secrets. Commits/pushes never trigger a build.
